  `pytest-socket` was added as a permanent enforcement mechanism so this
  class of bug can't silently reappear.

## Open threads / possible next steps

The user's own framing for the next session: **"we're going on to
integrating scrapes to matches."** Concretely, this means connecting the
1045 postings now sitting in `scraper/jobs/*.md` to `resume-matcher`'s
scoring pipeline. Relevant existing state to build on, not re-derive:

1. The integration point already exists and is documented:
   `scraper/README.md` (lines ~77–86, "Integration with resume-matcher")
   shows `cd ../resume-matcher && python job_matcher.py --resumes
   "resumes/*.md" --jobs "../scraper/jobs/*.md" --mode embed`. This has
   **not yet been exercised at this scale** (1045 real postings) — only
   conceptually verified in the original design plan with a handful of
   files. Actually running it and checking the results for sanity
   (does it crash on any of the 20 sites' markdown formatting quirks?
   does ranking behave sensibly across nearly 200x more postings than any
   prior test batch?) is the natural first step.
2. `resume-matcher/job_matcher.py` accepts `--jobs` (glob, `nargs="+"`) and
   `--jobs-file` (a text file of glob patterns, one per line) — the latter
   might be worth using if the next session wants to score against a
   curated subset of the 20 sites rather than all of them at once.
3. Consider whether "integrating scrapes to matches" implies something
   beyond a manual CLI invocation — e.g., a small combined script/Makefile
   target that runs `scraper`'s `scrape --site all` and then immediately
   feeds the output into `resume-matcher`, or a scheduled/repeatable
   pipeline. This is a scope question the user hasn't answered yet — worth
   clarifying early rather than assuming a specific shape.
4. Not yet done, lower priority than the above: **push the 24 local commits
   to `origin/main`**. The user has asked for push at epic boundaries in
